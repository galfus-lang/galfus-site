# Database schema

This package is the only source of truth for the Galfus SurrealDB schema. Do not
add or run standalone `.surql` schema files from an app.

Install the pinned SurrealKit CLI once:

```sh
cargo binstall surrealkit --version 1.0.0-beta.1
```

If `cargo-binstall` is not installed, compile it from source instead:

```sh
cargo install surrealkit --version 1.0.0-beta.1
```

Ensure Cargo's bin directory is in `PATH`. In environments where that is not
possible, set `SURREALKIT_BIN` to the absolute path of the executable.

## Targets

Each command selects exactly one database target. There is no default sync
command, preventing a schema change from reaching a cloud database by mistake.

| Target | Connection |
| --- | --- |
| `local` | `ws://127.0.0.1:8000/rpc`, namespace `development`, database `main`; each value can be overridden with `SURREALDB_LOCAL_*`. |
| `development` | Cloud database configured exclusively with `SURREALDB_DEVELOPMENT_*`. |
| `production` | Cloud database configured exclusively with `SURREALDB_PRODUCTION_*`. |

Cloud targets require these variables:

```sh
SURREALDB_DEVELOPMENT_HOST=wss://...
SURREALDB_DEVELOPMENT_NAMESPACE=development
SURREALDB_DEVELOPMENT_NAME=main
SURREALDB_DEVELOPMENT_USER=root
SURREALDB_DEVELOPMENT_PASSWORD=...

SURREALDB_PRODUCTION_HOST=wss://...
SURREALDB_PRODUCTION_NAMESPACE=production
SURREALDB_PRODUCTION_NAME=main
SURREALDB_PRODUCTION_USER=root
SURREALDB_PRODUCTION_PASSWORD=...
```

Run a dry-run before every sync:

```sh
bun run schema:local:check
bun run schema:development:check
bun run schema:production:check
```

Sync the explicit target:

```sh
bun run schema:local:sync
bun run schema:development:sync
bun run schema:production:sync
```

The cloud sync commands opt in to SurrealKit's shared-prune guard, so they can
make the selected database exactly match this repository. Use the check command
first; a sync can remove managed definitions absent from these files.

## Generated record types

`src/generated/index.ts` is generated by SurrealKit from the selected live
database and is committed to the repository. It exports the table interfaces
(`Account`, `AccountIdentity`, `AccountKey`, `Organization`, and others) with
SurrealDB `RecordId` and `Date` types.

After syncing the chosen environment, regenerate explicitly when needed:

```sh
bun run schema:local:typegen
bun run schema:development:typegen
bun run schema:production:typegen
```

The JSON introspection snapshot in `database/types/` is intentionally ignored:
it includes generation metadata and is not the application type source. Valibot
continues to validate user-controlled input in `src/schemas.ts`; it does not
duplicate persisted record definitions.

## Data access API

Applications own the `Surreal` connection and inject it into functions exported
by `@galfus/data-manager/server`. These functions validate `unknown` inputs
with Valibot, discard fields outside the operation contract, and return either
typed data or a structured validation/conflict error. HTTP responses, sessions,
cookies, JWTs, and connection configuration remain in the application.
